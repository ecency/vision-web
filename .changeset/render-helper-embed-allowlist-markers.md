"@ecency/render-helper": patch
---

The embed allow list and render-helper's link markers now hold on every render path. The sanitizer keeps an `<iframe>` only when `isAllowedEmbedSrc` accepts its src (an iframe with a refused src is dropped) and trims an author's `sandbox` to the tokens render-helper grants (`allow-scripts allow-same-origin allow-popups`). Every allowed embed host now has an embed path shape, matching what `iframe()` accepts. `iframe()` emits only sources the allow list accepts: http and protocol-relative embeds are upgraded to https, upper case YouTube `/EMBED/` is lower-cased, BitChute `/video/` and Brighteon page URLs frame their embed route, and a YouTube Shorts URL without an 11 character id shows the unsupported placeholder. Spotify `embed-podcast` paths are on the allow list. Author-written `markdown-*` classes and the `data-*` attributes render-helper sets on its own links are stripped before the transforms run, attribute names are lower-cased before parsing so upper case spellings get the same treatment, and `<` / `>` in text are escaped before tags and mentions are linked, so escaped markup in a body stays text. `<video poster>` is served through the image proxy, and dropped when it is not. The sanitize-only fallback applies the same rules itself: images through the proxy, no author `target`/`rel`, no author markers. Full renders now enforce this at the output boundary: every element the transformed DOM serializes carries a per-render nonce, and the final sanitizer keeps render-helper's link markers and link policy only on those, while images and posters must be on the image proxy everywhere. `<script>`/`<style>` (with their content), comments, processing instructions and malformed element names are dropped, and CDATA renders as text. Author `rel`/`target` are removed from app links, same-document links and fake author/tag chips pointing off-site. A YouTube URL in non-autolinked text keeps the text around it, and `simpleMarkdownToHTML` canonicalises the embed URLs the full render would (YouTube `/EMBED/` and Shorts, BitChute `/video/`, Brighteon pages). The boundary relies on `@xmldom/xmldom` 0.9.12 serialisation and `xss` 1.0.15 tokenisation, so both are now pinned exactly: consumers get exactly these versions instead of a caret range, and a bump needs the differential fuzz and corpus differential re-run (see the package README). URL attributes the sanitizer validates are emitted exactly as validated, so a double-encoded reference (`&#38;#47;`) can no longer decode past the check in the browser.
